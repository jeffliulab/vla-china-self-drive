# 课程大纲（鬼探头 VLA 自动驾驶）：8 节核心 + 1 节选修

第一~五课把 [carla熟悉教学.md](carla熟悉教学.md) 里的 11 个 Stage（0–10）**重组为 5 节课程**：每节课一个主题、一个能跑能看的产物。**第六~九课是 Stage 10 之后的净新单元**，把课程终点对齐到 [实验设计.md](实验设计.md) 定义的**三方 ablation**（rule / zero-shot / 微调 VLA）与**四件产出**（HF Dataset / HF Model / GitHub / 论文）——原 5 课只交付了前两方，微调 VLA 整条链（规模化数据→微调→三方评测→论文）由第六~八课补齐，第九课为选修拔高。环境实测以 [CLAUDE.md](../CLAUDE.md) 为准（`carla9` / CARLA 0.9.16 / Low 画质）。

## 第一课 — 进入 CARLA 世界（Stage 0 + 1 + 2）

**主题**：先建立心智模型，再把 server 跑起来、Python 连上去，最后第一次 spawn 车并干净销毁。建立「我能控制这个世界」的体感。

- **A. 心智模型（Stage 0，无代码）**：自动驾驶软件栈（感知→预测→规划→控制）、CARLA 的 server-client + 游戏引擎机制、「鬼探头」为什么难。
- **B. 跑起来 + 连上（Stage 1）**：启动 server；`carla.Client` 连接；打印版本/当前地图/可用地图列表；切到 `Town05`；移动 spectator；先跑官方 `manual_control.py`、`generate_traffic.py`。
- **C. Actor 与 Blueprint（Stage 2）**：`get_blueprint_library` → `try_spawn_actor` → `destroy` 全流程；spawn ego + N 辆 NPC 开 autopilot；**验证二轮车能否 spawn**；统一 `cleanup()`。

**产物**：`scripts/health_check.py`（连接巡检）+ `scripts/asset_inventory.py`（导出可 spawn 资产清单 JSON）。
**验收**：能手动开车转一圈；脚本能切地图并打印信息；能稳定 spawn+干净销毁；产出资产清单。
**常见坑**：client/server 版本必须都 0.9.16；`set_timeout` 太短连不上；spawn point 被占返回 `None`；脚本崩了 actor 残留 → 重启 server 或先清场。

## 第二课 — 让世界可复现、能「看」（Stage 3 + 4）

**主题**：同步模式 + 固定时间步（可复现的命门）；给车挂相机，把图像取进 numpy、实时显示并按帧存盘（VLA 的「眼睛」）。

- 同步 vs 异步；`synchronous_mode=True` + `fixed_delta_seconds=0.05`（20FPS）；TrafficManager 同步；主循环 `while: world.tick()`。
- RGB / depth / semantic 相机；`carla.Transform` 挂载；`camera.listen(callback)`；BGRA→numpy；pygame/opencv 显示；逐帧对齐存盘。

**产物**：确定性同步循环脚本 + 实时前视窗口 + 按帧存图（与 tick 对齐）。
**验收**：能解释「为什么采集必须同步+固定步长」；同 seed 两次运行轨迹一致；前视窗口能跑、能存帧。

---

## 第三课 — 让车会动、会刹、有人（Stage 5 + 6）

**主题**：spawn 行人并能「脚本化精确横穿」（鬼探头的人）；把高层动作翻译成 `VehicleControl`，做出会沿路开、遇障急刹的规则 baseline（既是对照，也是采数据的 expert）。

- 行人 AI 控制器 `controller.ai.walker` vs 手动 `WalkerControl(direction, speed)`（窜出用手动最可控）。
- `VehicleControl(throttle, steer, brake)`；纵向 PID + 横向沿 waypoint；可复用官方 `agents/navigation`（`BasicAgent`/`LocalPlanner`）；高层动作集 → 控制映射。

**产物**：「行人窜出」函数 + 会刹车的规则 baseline。
**验收**：行人能自然走、也能在「下令」瞬间精确横穿；ego 能自动跑完一条路线、前方有人能刹停。

---

## 第四课 — 搭鬼探头舞台 + 录数据（Stage 7 + 8）

**主题**：组装可复现、可配置、可判定成败的鬼探头场景；把一次运行完整录成 episode（图像+状态+动作标签+元信息），批量产出 SFT 小数据集。

- 场景三要素：遮挡物 + 藏在后面的行人 + 触发条件；固定 `seed` 复现；`reset()`；成败判据（碰撞/安全停住/`min_TTC`）；进阶 ScenarioRunner / Scenic。
- episode 数据结构（`frames/`、`states.parquet`、`actors.parquet`、`labels.jsonl`、`meta.json`）；同步逐帧对齐落盘；连续控制反推高层动作标签。

**产物**：可复现鬼探头场景（YAML 可配）+ `record_episode.py` + N 条 episode。
**验收**：同 seed 完全复现；规则 baseline 在此场景有时刹停有时撞上（难度真实）；磁盘上有结构规整、可复看的 N 条 episode。

---

## 第五课 — VLA 闭环 + 评测交付（Stage 9 + 10）

**主题**：把「看图像 + 读中文指令 → 输出高层动作」的 VLA 接进闭环（先 zero-shot VLM，不训练也能跑）；用统一指标评测、对比基线、产出结果表 + 演示视频。

- prompt = 前视图 + 自车状态(文本) + 中文指令 + **允许动作集**（结构化选一个）；高层动作 → 第三课控制器；1–2Hz 查模型、中间帧控制器顶住（闭环延迟 ~1–1.5s 是已知特性）。
- 指标：`scenario_success` / `collision_count` / `min_ttc` / `hard_brake_count` / `instruction_compliance`；多 seed 统计；rule vs zero-shot VLA（进阶：QLoRA 微调小 VLM 再加一列）。

**产物**：`vla_agent.py`（闭环）+ `eval.py`（指标表）+ 演示视频（可在 0.10.0 高画质复现）。
**验收**：VLM 驱动的 ego 能跑完场景并对鬼探头做出反应；一张「rule vs zero-shot VLA」对比表 + 一段演示视频。**做到这步，zero-shot 闭环跑通＝三方 ablation 的前两方完成**；微调 VLA（第三方）与论文交付见第六~八课。

---

## 第六课 — 规模化数据采集 + 数据集发布（净新 · Stage 之后）

**主题**：把第四课的 demo 级 `record_episode.py` 跑成**可训练规模**的数据集，清洗、构造 SFT 样本、切分、发布到 HuggingFace——这是微调 VLA 的燃料。概念复用 [§5.6](自动驾驶笔记/1-自动驾驶模型.md)（采集流程）、[§5.7](自动驾驶笔记/1-自动驾驶模型.md)（监督 vs 模仿数据）。

- **规模化采集**：多 seed + 场景参数随机化（触发距离 D、行人速度、遮挡车型、天气），用规则 baseline（expert）批量跑；**动作分布均衡**——`STOP`/`SLOW_DOWN` 是长尾，需主动造危险场景补采（[§5.2](自动驾驶笔记/1-自动驾驶模型.md)）。
- **清洗**：剔除坏帧/失败 episode，校验图像-状态-标签逐帧对齐。
- **构造 SFT 样本**：把「前视图 + 状态文本 + 中文指令 + 允许动作集 → 高层动作标签」整理成 Qwen2.5-VL 对话格式；守 [§3.2](自动驾驶笔记/1-自动驾驶模型.md) 红线（被遮挡 actor 真值**不进**模型输入）。
- **切分 + 发布**：按 seed/场景切 train/val/test（防泄漏）；上传 HF Datasets（dataset card / license / 版本号）。

**产物**：可训练规模的 **HF Dataset**（含 dataset card）。
**验收**：能从 HF 下载并加载；给出动作分布表；train/val 无泄漏；样本格式可直接喂第七课训练脚本。
**常见坑**：动作长尾（危险动作太少→训不出避让）；数据落 git（应走 `.gitignore`，存 `data/`）；同 seed 的帧跨 train/val 造成泄漏。

## 第七课 — QLoRA 微调 + 接回闭环（净新 · Stage 之后）

**主题**：用第六课数据 QLoRA 微调 Qwen2.5-VL-3B，导出 adapter 上传 HF，并把微调权重**接回 `vla_agent`**，得到三方 ablation 的第三个 agent。概念复用 [§5.4](自动驾驶笔记/1-自动驾驶模型.md)（架构/QLoRA）、[§5.5(6)(7)](自动驾驶笔记/1-自动驾驶模型.md)（显存/训练路线）。

- **第一步先定训练环境**：torch 现只在 `isaaclab`、`carla9` 无 torch（CLAUDE.md §3）；微调须**离线做（关掉 CARLA）**或上服务器（PROJECT_PLAN §7）；16 GB 本机硬刚 OpenVLA-7B 不可行（§5.5(7)）。
- **微调**：QLoRA（4-bit 量化 + LoRA）；结构化/受限输出约束到允许动作集；监控 loss 与 val 动作准确率；导出 adapter 上传 HF。
- **接回闭环**：微调 agent 与 zero-shot **共用同一闭环接口**（保证三方公平对比）。

**产物**：**HF Model**（QLoRA adapter）+ 接回闭环的微调 agent（第三个 agent）。
**验收**：训练收敛、val 动作准确率合理；微调 agent 在鬼探头场景闭环跑通；权重可从 HF 加载复现。
**常见坑**：CARLA 与训练抢同一张卡（训练时关 CARLA）；小数据过拟合；微调后输出仍需强约束动作集。

---

## 第八课 — 三方评测 + 论文交付（净新 · Stage 之后）

**主题**：rule vs zero-shot vs 微调**三方**统一跑指标、写论文、收尾 GitHub、出高画质 demo——交付实验设计定义的完整终点。概念复用 [§5.5(8)](自动驾驶笔记/1-自动驾驶模型.md)（四件产物/复现性边界）、[§5.8](自动驾驶笔记/1-自动驾驶模型.md)（SOTA 坐标/升级路线）。

- **三方评测**：固定 seed 集上统一跑 `scenario_success / collision_count / min_ttc / hard_brake_count / instruction_compliance`，多 seed 统计。
- **复现性边界**（[§5.5(8)](自动驾驶笔记/1-自动驾驶模型.md)）：API agent 锁模型版本号、`temperature=0`、prompt + 原始响应全量落盘；报告区分三档可复现性（rule/expert 完全可复现 ↔ 本地微调可复现 ↔ API 近似可复现）。
- **写论文**：引言 / **相关工作**（含 [§5.8](自动驾驶笔记/1-自动驾驶模型.md) 的 SOTA 坐标：UniAD·VAD·EMMA·GAIA / DriveVLM·LMDrive / 双系统定位）/ 方法（分层 VLA + 鬼探头）/ 实验（三方 ablation）/ **讨论与未来工作**（§5.8 的 v2/v3 升级路线）。求职定位话术并入论文，不另起文件。
- **收尾**：GitHub（README / 复现说明 / configs / 清理）；0.10.0 高画质 demo 视频。

**产物**：三方对比表 + 论文 + 收尾的 GitHub repo + demo 视频。
**验收**：三方表多 seed 有统计；论文含相关工作 + 未来工作；repo 能按 README 复现核心结果。**做到这步，三方 ablation + 四件产出全部交付，项目真正闭环完成。**
**常见坑**：只看单 seed（必须多 seed 才有说服力）；只报成功率不报安全指标（min_ttc/碰撞同样重要）；API 不锁版本→不可复现。

---

## 第九课（选修·拔高）— v2 轨迹级输出 + 滚动重规划（净新 · 项目完成后）

> **本课是 post-MVP 加分项**：项目已在第八课闭环完成，**v2/v3 非三方 ablation 所需**。目的是把项目贴近 AD SOTA、面试更有的聊。概念复用 [§5.8(1)(2)(4)](自动驾驶笔记/1-自动驾驶模型.md)（动作表示谱系 / 时延陷阱 / 升级路线 v1→v2→v3）。

- **v2**：高层从离散动作升级为「短轨迹 / 目标路点序列」；下游用 MPC / 纯跟踪；每周期**滚动重规划（receding horizon）**。
- **（可选 v3）**：异步推理 / 实时分块（temporal ensembling）抗时延陷阱（[§5.8(2)](自动驾驶笔记/1-自动驾驶模型.md)）。
- 对标 AD SOTA：UniAD / VAD / EMMA / DiffusionDrive。

**产物**：升级版 agent（轨迹级 + 滚动重规划），与 v1 离散动作对比（非必需）。
**验收**：能讲清 options↔轨迹↔chunk 谱系与时延陷阱三种解法；v2 agent 跑通并与 v1 对比。
**常见坑**：别在 MVP 前做；轨迹跟踪器调参；异步带来的时序对齐复杂度。
