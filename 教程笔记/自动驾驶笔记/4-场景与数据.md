## 1. 心智模型①：鬼探头场景 = 三要素 + 可复现 + 成败判据

第一课 [§3](1-自动驾驶模型.md) 讲了鬼探头为什么是 POMDP，本课把它**做出来**。

### 1.1 三要素

```
行驶方向 →
──────────────────────────────────────────
   🚌 遮挡物(路边停的公交/货车)
   🚶 藏在遮挡物后的行人(ego 相机看不见 = 隐藏状态)
──────────────────────────────────────────
🚗 ego ──(进入触发距离 D)──► 触发：行人手动 WalkerControl 直线窜出
```

1. **遮挡物**：路边停的大车，**必须真挡住 ego 相机视线**（用 spectator 或语义图确认，否则失去"鬼探头"意义）。
2. **藏后行人**：一开始就 spawn 在遮挡物后、**一直存在但不可观测**（第一课 [§3.1](1-自动驾驶模型.md) 的隐藏状态 $s_t$）。
3. **触发条件**：ego 进入触发距离 $D$ 时，用第三课的手动 `WalkerControl` 让行人**精确窜出**。

### 1.2 可复现：一条完整的"锁随机"链

第二课讲了同步+固定步长是地基，但**可复现要锁住所有随机源**：

| 随机源 | 怎么锁 |
|---|---|
| 时间推进 | 同步 + `fixed_delta_seconds`（第二课） |
| NPC 车流 | `tm.set_synchronous_mode(True)` + `tm.set_random_device_seed(seed)` |
| 行人导航 | `world.set_pedestrians_seed(seed)` |
| 触发时机 | **用"距离阈值"触发，不要用墙上时间/随机**（距离由确定性物理决定 → 可复现） |
| 天气/光照 | `world.set_weather(固定预设)` |
| spawn 位置 | 写死或由 seed 决定，别用 `random` 不带种子 |

> `reset(seed)`：把上面全部按 seed 复位。**同 seed 两次运行，轨迹、行人窜出时机、碰撞与否完全一致**——这是第八课评测可信度的前提（第一课 [§5.5(8)](1-自动驾驶模型.md) 的"框架可复现"）。

### 1.3 成败判据（必须可自动判定）

| 判据 | 怎么测 | 含义 |
|---|---|---|
| **碰撞** | 碰撞传感器 `sensor.other.collision` 触发 | 撞到行人 = 失败 |
| **安全通过** | 行人横穿事件解决且全程无碰撞、ego 完成路线 | 成功 |
| **min_TTC** | 整段最小 TTC（[§3.2](#32-min_ttc危险度量怎么算) 算法） | 即使没撞，TTC 太小也算危险（衡量"险不险"） |

> 难度要"真实"：调好触发距离 $D$ 与行人速度，使**规则 baseline 有时刹停、有时撞上**。要么必撞、要么没威胁，都说明场景没调好。

## 2. 心智模型②：episode = 一次运行的完整录像

一个 **episode** = 跑一遍场景，把**每一帧的所有东西**对齐落盘。它是后面微调的 SFT 数据来源（第一课 [§5.6/§5.7](1-自动驾驶模型.md)）。

数据结构（PROJECT_PLAN §8）：

```
episode_000001/
  meta.json          # carla_version, map, scenario, weather, seed, fps, sensors
  config.yaml        # 场景参数(D、行人速度、遮挡车型…)
  frames/
    rgb_front/000123.png
    depth_front/000123.png
    semantic_front/000123.png
  states.parquet     # 每帧 ego: 速度/加速度/yaw/位置/目标waypoint
  controls.parquet   # 每帧 throttle/steer/brake
  actors.parquet     # 每帧周围 actor 的位置/速度
  labels.jsonl       # 每个决策步的高层动作标签(+第八课起：prompt+原始响应)
```

要点：**逐帧对齐**（靠第二课的同步+队列+帧号），否则图像和状态错位、数据全废。

## 3. 必须知道的原理

### 3.1 连续控制 → 高层离散动作标签（行为克隆的"标签"从哪来）

第一课 [§5.1/§5.6](1-自动驾驶模型.md) 说本项目训"图像+指令→**高层离散动作**"。但 expert（规则/BehaviorAgent）输出的是**连续** `throttle/steer/brake`。所以要**反推**离散标签：

```
观察 expert 这一段的(控制 + 状态)：
  brake 大且在减速、前方有威胁  → 标 STOP / SLOW_DOWN
  横向偏移到邻车道完成          → 标 CHANGE_LEFT/RIGHT
  路口按某分支转向              → 标 TURN_LEFT/RIGHT
  正常巡航                      → 标 KEEP_LANE
```

这是一个**规则化的"行为抽象"**（把低层动作归纳成高层意图）。它把"专家怎么开"翻译成"专家做了什么高层决策"，得到 (图像+状态+指令 → 高层动作) 的监督对。**这正是第一课 [§5.7](1-自动驾驶模型.md) 说的"从富录像派生训练对"。**

### 3.2 min_TTC：危险度量怎么算

第一课 [§4.5](1-自动驾驶模型.md) 给了 $\text{TTC}=d/\max(v_{\text{closing}},0)$。本课把它落成评测量：

- 每帧对**视线内可见**的前向目标算 TTC（守第一课 [§3.2](1-自动驾驶模型.md) 红线：**别用被遮挡行人的真值**算，否则等于上帝视角）。
- 距离 $d$ 与接近速度 $v_{\text{closing}}$ 来源：深度相机 / 雷达 / 可见 actor 真值（第一课 [§2.5/Q16](1-自动驾驶模型.md)）。
- 整段取最小 → `min_TTC`。它衡量"这次有多险"，即使没撞，`min_TTC` 很小也说明策略危险。

### 3.3 主动造场景采样（对抗长尾）

第一课 [§5.2](1-自动驾驶模型.md)：危险场景在自然数据里是长尾，采不到。本课的解法就是**用脚本主动批量造**：

- 在多个 seed 上重复跑鬼探头，**系统地变化**参数（触发距离、行人速度、遮挡车型、天气）。
- 这样能采到大量"危险时刻 + 专家正确处置"的样本，**人为补上长尾**。
- 这也是为什么本项目"先造场景再采数据"，而非"开着采自然数据"。

### 3.4 进阶：ScenarioRunner / Scenic（先了解）

手写触发逻辑能跑通；规模化后可用专业工具：
- **ScenarioRunner**：`BasicScenario` + py_trees 行为树 + 内置评测 criteria，CARLA 官方场景框架。
- **Scenic**：用一种概率场景描述语言声明式地生成场景。
本课先手写，知道有这两个"工业级"选项即可。

## 4. 实践：CARLA Python client

### 4.1 API 速查（本课新增）

| 目的 | 调用 |
|---|---|
| 碰撞检测 | `col_bp=bp_lib.find('sensor.other.collision')`；`col=world.spawn_actor(col_bp, carla.Transform(), attach_to=ego)`；`col.listen(on_collision)` |
| 障碍距离 | `sensor.other.obstacle`（报前方最近障碍距离）/ 深度相机 |
| 天气 | `world.set_weather(carla.WeatherParameters.ClearNoon)` 或自定义 |
| 导航网格点 | `world.get_random_location_from_navigation()` |
| 行人可复现 | `world.set_pedestrians_seed(seed)` |
| 存 parquet | pandas/pyarrow（注意 `carla9` 默认未装 pyyaml/部分库，按 CLAUDE.md §3 先 `pip install`） |

### 4.2 场景类骨架（写代码前征得同意）

```
class GhostProbeScenario:
    def reset(self, seed):
        锁随机(同步/TM seed/pedestrian seed/天气)；spawn 遮挡物、藏后行人、ego+传感器+碰撞器
    def tick(self):
        world.tick()
        if dist(ego, occluder) < D and not self.triggered:
            行人.apply_control(WalkerControl(cross_dir, speed)); self.triggered=True
        更新 min_TTC
    def is_collision(self): return self.collided
    def is_success(self): return (not self.collided) and self.route_done
```

### 4.3 record_episode 骨架

```
开 episode 目录 + 写 meta.json/config.yaml
for step:
    scenario.tick()
    存 frames/(rgb/depth/semantic, 帧号对齐) + states/controls/actors(parquet 累积)
    由 expert 的(控制+状态)反推高层动作标签 → labels.jsonl
关 episode；多 seed 循环 → N 条
```

### 4.4 常见坑

- **遮挡没真挡住**（角度/高度不对）→ 相机其实看得见行人，鬼探头失效；先用语义图确认被遮挡。
- **触发用时间/随机而非距离** → 不可复现。
- **异步残留**（忘了第二课的同步）→ 图文错帧、数据废。
- **数据落 git** → CARLA 数据大，必须走 `.gitignore` 存 `data/`（第一课 [§5.6](1-自动驾驶模型.md)、CLAUDE.md 规则）。
- **把被遮挡行人真值写进 labels 的"模型输入"字段** → 越过第一课 [§3.2](1-自动驾驶模型.md) 红线（记录可以、喂给模型不行）。
- **难度没调** → 全成功或全失败，数据没信息量。

## 5. 验收 & 自测题

**操作验收**
- [ ] 同一 seed 下场景**完全复现**（轨迹、窜出时机、碰撞与否一致）。
- [ ] 规则 baseline 在此场景**有时刹停、有时撞上**（难度真实）。
- [ ] 磁盘上有结构规整、可复看的 N 条 episode；能加载任意一条检查图文/标签是否对齐。
- [ ] 场景参数（D、行人速度、遮挡车型）能用 YAML 配置。

**概念自测（能用自己话答上即过关）**
1. 鬼探头三要素是什么？为什么必须确认"真的被遮挡"？
2. 要让场景可复现，除了同步+固定步长，还要锁哪些随机源？触发为什么用距离而非时间？
3. expert 输出连续控制，怎么得到"高层离散动作标签"？这属于什么学习范式的数据？
4. `min_TTC` 怎么算？算它时为什么不能用被遮挡行人的真值？
5. 为什么本项目"先造场景再采数据"，而不是开着采自然数据？
