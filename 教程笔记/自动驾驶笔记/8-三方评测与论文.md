## 1. 心智模型①：三方 ablation 是一个科学问题（控制变量）

实验设计的核心是回答一个问题：**"微调 VLA 比 baseline 好吗？好在哪？"** 要回答得可信，必须**控制变量**——三方只许"决策大脑"不同，其余全一样：

```
rule baseline   ┐
zero-shot VLA   ├─ 同一鬼探头场景 + 同一控制器 + 同一指标 + 同一固定 seed 集 → 差异只归因于"大脑"
微调 VLA        ┘
```

- **rule**（第三课）：写死规则，对照下限。
- **zero-shot**（第五课）：通用 VLM，租来的大脑。
- **微调**（第七课）：你训练的 VLA，主结果。
- 三方共用第三课控制器、第四课场景、第五课指标——**只有大脑不同**，结论才站得住（第一课 [§5.5(8)](1-自动驾驶模型.md)）。

## 2. 心智模型②：可复现的三档

第一课 [§5.5(8)](1-自动驾驶模型.md) 的复现性边界，本课要在报告里**明确分档**：

| agent | 可复现性 | 为什么 |
|---|---|---|
| rule / expert baseline | **完全可复现** | 确定性规则 + 锁 seed |
| 微调 VLA（本地） | **可复现** | 权重你有、`temperature=0`、锁 seed |
| zero-shot VLA（API） | **近似可复现** | 服务端版本/采样/限流不由你控 → 必须锁版本号、`temperature=0`、prompt+原始响应全量落盘 |

> 关键认知：**可复现的是框架**（场景 seed、传感器、指标、数据管线），不是某个 API agent 的逐字输出。报告要诚实标注这三档（第一课 [§5.5(8)](1-自动驾驶模型.md)）。

## 3. 必须知道的原理

### 3.1 评测方法学：多 seed + 统计

- **固定 seed 集**：所有 agent 在**同一组 seed**上跑（同样的窜出时机/车流），才可比。
- **多 seed**：单 seed 没说服力；报**均值 ± 标准差**，必要时做显著性检验（seed 数够才有意义）。
- **闭环评测**：在 CARLA 里真跑（不是离线 test 集准确率）——闭环才暴露复合误差（第一课 [§4.4](1-自动驾驶模型.md)）。

### 3.2 指标体系：成功率 ≠ 全部

只报成功率会骗人，要三类一起看（PROJECT_PLAN §9）：

| 类 | 指标 | 防什么 |
|---|---|---|
| 完成 | `scenario_success` / `route_completion` | 任务有没有做成 |
| **安全** | `collision_count` / `min_ttc` / `hard_brake_count` | 防"靠急刹/险过兜底也算成功" |
| 合规 | `instruction_compliance` | 中文指令有没有真被遵守（本项目卖点） |

> 一个反例：某 agent 成功率高，但 `min_ttc` 极低、`hard_brake_count` 高 → 它是"每次都险过+急刹"，不安全。只看成功率会误判（第五课 [§3.5](5-VLA闭环与评测.md)）。

### 3.3 论文结构（含 §5.8 的 SOTA 与升级路线）

| 章节 | 写什么 |
|---|---|
| 引言 | 问题（中国式鬼探头/弱势交通参与者）、动机、贡献点 |
| **相关工作** | §5.8 的 SOTA 坐标：端到端 AD（UniAD/VAD/EMMA/DiffusionDrive）、VLM 开车（DriveVLM/LMDrive）、世界模型（GAIA）、双系统范式——**定位自己在谱系里的位置** |
| 方法 | 分层 VLA（VLM System2 + 控制器 System1）、鬼探头场景、动作集、数据管线 |
| 实验 | **三方 ablation 表** + 多 seed 统计 + 复现性分档 + 消融（如指令有无、动作约束有无） |
| 讨论与未来工作 | 局限；**§5.8 的 v2/v3 升级路线**（轨迹级 + 滚动重规划 + 异步）作为 future work |

> 求职话术（双系统定位、"我为什么选 options + 升级路线"）就**融进引言/相关工作/讨论**（课程口径：不另起文件）。

### 3.4 GitHub 收尾 = 可复现交付

- **README**：项目一句话、架构图、环境（对接 CLAUDE.md）、**一键复现核心结果的步骤**。
- **configs**：场景/传感器/seed 集/模型版本全部入配置，别散在代码里。
- **清理**：删死代码、补 `.gitignore`（数据/权重/视频不进 git）、HF 链接（Dataset/Model）。
- **demo**：0.10.0 高画质复现一段"成功避让鬼探头"的 episode 视频（PROJECT_PLAN 阶段 5）。

## 4. 实践：评测、论文、收尾

### 4.1 评测骨架（写代码前征得同意）

```
SEED_SET = 固定的一组评测 seed(与训练 seed 不相交)
for agent in [rule, zero_shot, finetuned]:
    for seed in SEED_SET:
        scenario.reset(seed); 闭环跑到结束
        收集 success/collision/min_ttc/hard_brake/instruction_compliance
        (zero-shot: 落盘模型版本+prompt+响应)
聚合 → 均值±std 三方对比表(results.md/csv)
```

### 4.2 论文/交付清单

```
□ 三方对比表(多 seed, 含安全指标)      □ 消融(指令有无/约束有无)
□ 论文(引言/相关工作/方法/实验/讨论)   □ README + 一键复现步骤
□ HF Dataset 链接 + HF Model 链接      □ 0.10.0 demo 视频
□ 复现性三档声明(第一课 §5.5(8))
```

### 4.3 常见坑

- **只看一个 seed** → 不可信（第五课同款坑，这里是底线）。
- **只报成功率不报安全指标** → 误判"险过型"agent（§3.2）。
- **三方用了不同控制器/场景/seed** → 对比不公平，结论作废（§1）。
- **API 不锁版本/不落盘** → zero-shot 那列无法复现，论文站不住（第一课 [§5.5(8)](1-自动驾驶模型.md)）。
- **train/test seed 重叠** → 微调那列虚高（第六课 [§3.5](6-规模化数据与发布.md)）。
- **README 没有一键复现** → 别人跑不起来，作品集大打折扣。

## 5. 验收 & 自测题

**操作验收**
- [ ] 三方在同一固定 seed 集、同一控制器/场景/指标下跑出多 seed 对比表（含安全指标）。
- [ ] 论文含相关工作（SOTA 定位）+ 未来工作（v2/v3）。
- [ ] repo 能按 README 一键复现核心结果；HF Dataset/Model 链接可用。
- [ ] 0.10.0 高画质 demo 视频。**做到这步 = 三方 ablation + 四件产出齐活，项目真正闭环。**

**概念自测（能用自己话答上即过关）**
1. 三方 ablation 为什么要"只许大脑不同、其余全一样"？
2. 三档可复现性分别是哪三档、为什么 API agent 只能"近似"？怎么把它逼到近似可复现？
3. 为什么"成功率高"不等于"好 agent"？要配哪些安全指标？
4. 论文的相关工作该放哪些 SOTA？未来工作放什么（提示 §5.8）？
5. 什么叫"可复现的是框架而非某个 agent"？
