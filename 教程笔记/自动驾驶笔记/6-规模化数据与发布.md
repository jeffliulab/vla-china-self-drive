## 1. 心智模型①：从 demo 数据到可训练数据集，差在哪

第四课能录 N 条 episode，但那是 **demo 级**（验证管线用）。要拿去微调，差四件事：

| 维度 | demo 级（第四课） | 可训练级（本课） |
|---|---|---|
| **规模** | 几条 | 足量（多 seed × 多参数组合，覆盖危险时刻） |
| **均衡** | 动作分布随意 | `STOP`/`SLOW_DOWN` 等关键动作有足够样本（对抗长尾） |
| **干净** | 可能有坏帧/错帧 | 清洗过、图文标签逐帧对齐 |
| **格式** | episode 原始结构 | 切成 (图+状态+指令 → 动作) 的 SFT 样本 + train/val/test |

> 一句话：**第四课解决"能不能录"，本课解决"能不能训"。**

---

## 2. 心智模型②：数据集 = 富录像 + 派生的训练对

复用第一课 [§5.7](1-自动驾驶模型.md) 的关键区分——**"录 vs 喂"**：

```
富录像(episode): 图像 + 全状态 + 全 actor metadata(含被遮挡真值) + 动作  ← 记录全量，为算指标/复现/转标签
        │  派生(守 §3.2 红线：被遮挡真值不进输入)
        ▼
SFT 训练对: 输入(前视图 + 可见状态文本 + 中文指令 + 允许动作集) → 标签(高层动作)
```

- **记录全量没问题**（算 min_TTC、复现、转标签都要用）；
- **但派生出的"模型输入"必须守红线**：被遮挡行人的真值**绝不进** SFT 样本的输入字段，否则训出来的模型是"作弊看穿遮挡"，鬼探头评测作废（第一课 [§3.2](1-自动驾驶模型.md)）。

## 3. 必须知道的原理

### 3.1 规模化与多样性（为什么要"多 seed + 参数随机化"）

第一课 [§4.4](1-自动驾驶模型.md) 的复合误差/协变量偏移告诉我们：模型部署时会走到训练没覆盖的状态。对策是**让数据尽量覆盖策略可能遇到的状态**：

- **多 seed**：同一场景不同随机实例（不同窜出时机、不同背景车流）。
- **参数随机化（domain randomization）**：系统地变化触发距离 $D$、行人速度、遮挡车型、天气、光照、起始车速。
- 目的：覆盖"危险时刻"的多种形态，让微调后的 VLA 不只会处理一种鬼探头。

### 3.2 动作分布均衡（对抗长尾 + 类不平衡）

第一课 [§5.2](1-自动驾驶模型.md)：危险动作天然稀有。自然跑出来的数据里 `KEEP_LANE` 会占绝大多数，`STOP`/`SLOW_DOWN` 很少 → **类不平衡**，模型会偷懒永远输出 `KEEP_LANE`。对策：

- **主动造危险场景补采**（第四课 [§3.3](4-场景与数据.md)）：专门多跑会触发减速/急停的配置。
- **重采样 / 加权**：训练时对稀有动作上采样或加 loss 权重。
- 出数据集时**给出动作分布表**，让使用者（和你自己）一眼看到平衡度。

### 3.3 清洗与质检

- **坏帧/坏 episode**：渲染异常、传感器丢帧、spawn 失败的 episode 剔除。
- **对齐校验**：用第二课的帧号确认 图像↔状态↔标签 逐帧对齐（错帧 = 脏数据）。
- **标签质检**：抽查"连续控制→高层动作"反推（第四课 [§3.1](4-场景与数据.md)）是否合理。

### 3.4 SFT 样本构造（对齐 Qwen2.5-VL 对话格式）

微调要把每条训练对写成模型认识的**多模态对话格式**，概念上：

```
messages = [
  {role: system,  content: "你是驾驶决策器，只能从允许动作集选一个，按 JSON 输出"},
  {role: user,    content: [ <image: 前视图>, "状态:速度.../车道...; 指令:注意公交车后可能有行人; 允许动作集:{...}" ]},
  {role: assistant, content: '{"action": "SLOW_DOWN"}'}    ← 训练标签(只对它算 loss)
]
```

- 输入与第五课 [§3.2](5-VLA闭环与评测.md) 的 prompt **保持一致**（训练/部署同分布，否则又是协变量偏移）。
- 标签就是高层动作（第四课反推的）。

### 3.5 切分：防泄漏

- **按 seed/场景切**，不按帧切：同一 episode 的相邻帧高度相关（第一课 [§1.2](1-自动驾驶模型.md) 非 i.i.d.），若把同一 episode 的帧分到 train 和 val，val 就"见过"了 → 虚高。
- train/val/test 用**不相交的 seed 集**；test 留出来给第八课评测（注意：闭环评测在 CARLA 里跑，不只是离线 test 集）。

### 3.6 发布 HF Dataset（可复现 + 可用）

- **dataset card**：说明场景、采集方式（谁是 expert）、动作集、字段、动作分布、license、已知偏差（哪些是仿真真值）。
- **版本号**：数据会迭代，锁版本便于复现（呼应第一课 [§5.5(8)](1-自动驾驶模型.md) 的"框架可复现"）。
- 大文件用 HF 的 LFS；**别进项目 git**（CLAUDE.md 规则）。

## 4. 实践：数据管线

### 4.1 管线骨架（写代码前征得同意）

```
1. scale_collect: 多 seed × 参数网格，用规则/BehaviorAgent expert 批量跑第四课场景 → 大量 episode
2. clean:         剔坏帧/坏 episode、校验对齐、标签质检
3. balance:       统计动作分布，对稀有动作补采/重采样/加权
4. to_sft:        episode → (图+状态文本+指令+动作集 → 动作) 的对话样本(jsonl)，守 §3.2 红线
5. split:         按 seed/场景切 train/val/test(不相交 seed)
6. publish:       写 dataset card + 版本，push_to_hub
```

### 4.2 常见坑

- **动作长尾没处理** → 模型永远输出 `KEEP_LANE`（看似"准确率高"实则没学会避让）。
- **按帧切而非按 seed/episode 切** → 数据泄漏、val 虚高。
- **训练输入格式与第五课部署 prompt 不一致** → 训练/部署分布不符（协变量偏移）。
- **被遮挡真值混进 SFT 输入** → 越红线，作弊（第一课 [§3.2](1-自动驾驶模型.md)）。
- **数据进 git** → 仓库爆炸；走 `.gitignore` + HF LFS。
- **没写 dataset card / 不锁版本** → 别人（和未来的你）无法复现。

## 5. 验收 & 自测题

**操作验收**
- [ ] 能从 HF 下载并加载你发布的数据集。
- [ ] 给出动作分布表，关键动作（STOP/SLOW_DOWN）样本量足够。
- [ ] train/val/test 按 seed 切、无泄漏；样本格式可直接喂第七课训练脚本。
- [ ] dataset card 写清场景/expert/动作集/license/版本。

**概念自测（能用自己话答上即过关）**
1. demo 数据和可训练数据集差哪四件事？
2. 为什么动作分布会长尾？不处理会怎样？三种对策是什么？
3. 为什么要"按 seed 切"而不是"按帧切"？（提示：i.i.d.）
4. "录全量"和"喂模型"为什么不矛盾？红线是什么？
5. SFT 样本的输入为什么要和第五课部署 prompt 保持一致？
