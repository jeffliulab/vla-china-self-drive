## 1. 心智模型①：异步 vs 同步——时间谁推进

第一课 [§2.2](1-自动驾驶模型.md) 点过概念，这里讲透，因为它是**采集数据的地基**。

### 1.1 两种模式的本质区别

```
异步 (默认)：server 按墙上时钟自己跑 ──► client 来取数时，给「最近一帧」
            ▲ server 不等你；你算得慢 → 丢帧；帧率随机器负载抖动 → 不可复现

同步：       server 跑完一步就停住等你 ──► 你调 world.tick() 它才推进一步
            ▲ 时间由你掌控；多慢都不丢帧、不错帧 → 可复现
```

- **异步**：`server` 自顾自按真实时间推进，`client` 拿到的是"此刻最新的一帧"。你的脚本若处理慢，世界已经往前跑了好几步——**帧率不稳、两次运行不一致**。
- **同步**：`settings.synchronous_mode = True`，`server` 每推进一步就**阻塞等待** `world.tick()`。你不调 `tick()`，世界就冻结。

### 1.2 为什么采集/评测必须同步（三个硬理由）

1. **可复现**：同 seed + 同 `fixed_delta_seconds` → 数值积分逐步确定（[§3.1](#31-离散步长与物理子步) 讲积分）→ 两次运行轨迹一致。这是科研可信度的底线。
2. **传感器对齐**：同步下每个 `tick` 所有传感器出**同一时刻**的帧；异步下相机 A 和相机 B 可能差好几帧 → 图像与状态错位，标签全废。
3. **慢推理不致命**：这正是第一课 [§5.5(5)](1-自动驾驶模型.md) 的「时间红利」——VLA 推理慢，同步下 server 会停下来等，**车的行为完全正确**，只是墙上时钟变慢。

> 一句话：**异步是「实时演示」用的，同步是「采数据 / 评测 / 接慢 VLA」用的。本项目从第四课起一律同步。**

### 1.3 别忘了 TrafficManager 也要同步

`TrafficManager`（管 NPC 车流，`set_autopilot(True)` 背后）有自己的节拍。开了世界同步却忘了 `tm.set_synchronous_mode(True)` → NPC 行为和你的 tick 不同步、依然不可复现。**两个都要设。** 还要 `tm.set_random_device_seed(seed)` 才能锁住 NPC 的随机性。

## 2. 心智模型②：传感器 = 挂在车上的子 actor

第一课 [§2.3](1-自动驾驶模型.md) 说「一切皆 actor」，传感器也是 actor，而且是**挂在车上的子 actor**。

```
camera_bp (蓝图)
   │  world.spawn_actor(camera_bp, transform, attach_to=vehicle, attachment_type=Rigid)
   ▼
camera (actor, 跟着车跑)
   │  camera.listen(callback)   ← 注册回调：每出一帧就调一次你的函数
   ▼
回调里：raw_data(字节流) → numpy → 你的处理
   │  用完 camera.stop() / camera.destroy()
```

三个关键点：

1. **`attach_to=vehicle`**：相机的位姿是**相对车体**的（第一课 [§4.1](1-自动驾驶模型.md) 的 $T_{\text{vehicle}\leftarrow\text{sensor}}$）；车动相机跟着动。
2. **`attachment_type`**：`Rigid`（刚性，采集用这个，位姿精确）vs `SpringArm`/`SpringArmGhost`（弹簧臂，第三人称跟拍平滑，演示用）。
3. **`listen(callback)` 是事件驱动**：传感器出帧就回调，**不是你主动去 read**。同步模式下，每个 `tick` 每个传感器恰好出一帧（受 `sensor_tick` 控制）。

### 2.1 本项目要挂哪些（PROJECT_PLAN §5.1）

| 传感器 | blueprint | 给什么 | 本项目用途 |
|---|---|---|---|
| RGB 相机 | `sensor.camera.rgb` | 2D 渲染图（无深度） | **VLA 的眼睛**（主输入） |
| 深度相机 | `sensor.camera.depth` | 每像素真实距离（引擎真值） | 安全层算 TTC、可视化 |
| 语义相机 | `sensor.camera.semantic_segmentation` | 每像素类别真值 | 造场景/标签、验证遮挡 |

> 详细传感器种类见第一课 [§2.5](1-自动驾驶模型.md)（CARLA 还有 LIDAR/RADAR/障碍检测等）。

## 3. 必须知道的原理

### 3.1 离散步长与物理子步

第一课 [§4.2](1-自动驾驶模型.md) 讲了 $x_{k+1}=f(x_k,u_k)$、$\Delta t=0.05$s、$f$=物理积分。这里补一个采集会踩的坑：**物理子步（substepping）**。

`fixed_delta_seconds` 太大，物理积分会不准（穿模、抖动）。CARLA 把一个大步**拆成若干物理子步**来积分，约束是：

$$
\texttt{fixed\_delta\_seconds} \le \texttt{max\_substeps} \times \texttt{max\_substep\_delta\_time}
$$

默认 `max_substep_delta_time=0.01`、`max_substeps=10` ⟹ 上限 0.1s。我们用 0.05s（5 个子步），安全。

> 落地：设 `fixed_delta_seconds` 时别超过 0.1；要更稳的物理就调小（如 0.025=40Hz），但要权衡墙上时钟变慢。

### 3.2 三种相机的数据编码（最容易栽的地方）

传感器回调拿到的 `image.raw_data` 是**字节流**，三种相机解码方式不同：

**(1) RGB**：BGRA 字节流。
```
array = np.frombuffer(image.raw_data, dtype=np.uint8).reshape((H, W, 4))  # BGRA
bgr   = array[:, :, :3]          # 丢掉 alpha
rgb   = bgr[:, :, ::-1]          # ★ BGRA→RGB 要翻通道，否则图发蓝（最常见坑）
```

**(2) 深度**：距离被编码进 R/G/B 三通道，要解码成米：
$$
\text{normalized}=\frac{R + G\cdot256 + B\cdot256^2}{256^3-1},\qquad
\text{depth(m)} = 1000 \times \text{normalized}
$$
（量程 0–1000m）。或直接用 `image.convert(carla.ColorConverter.Depth)` 做可视化、`LogarithmicDepth` 看近处细节。

**(3) 语义分割**：**类别 id 存在红色(R)通道**里（每个像素一个整数标签：路/车/人/建筑…）。可视化用 `carla.ColorConverter.CityScapesPalette` 上色。类别 id 对照表见官方 *Sensors reference*（版本不同 id 会变，别硬记）。

### 3.3 相机内参与投影（深化第一课 §4.6）

第一课 [§4.6](1-自动驾驶模型.md) 给了针孔模型 $s[u,v,1]^\top = K[R\mid t][X,Y,Z,1]^\top$。CARLA 相机的内参由 `image_size_x` 和 `fov` 决定：

$$
f = \frac{\texttt{image\_size\_x}}{2\tan(\texttt{fov}\cdot\pi/360)},\quad
c_x=\frac{\texttt{image\_size\_x}}{2},\ c_y=\frac{\texttt{image\_size\_y}}{2},\quad
K=\begin{bmatrix}f&0&c_x\\0&f&c_y\\0&0&1\end{bmatrix}
$$

**什么时候用**：把深度图某像素 $(u,v)$ + 深度 $d$ 反投影成 3D 点（算 TTC、把语义/深度对齐到 3D）。流程：像素 → 相机系（用 $K^{-1}$）→ 世界系（用第一课 §4.1 的外参 $T$）。**这是第四课算 `min_TTC`、第五课给 VLA 喂结构化空间信息的基础**。

### 3.4 时间对齐：用「队列」把帧锁到 tick

同步模式下 `listen` 回调仍是**异步触发**的——你 `world.tick()` 后，回调可能稍晚才把帧塞进来。直接在主循环读会拿到**上一帧**。标准解法是**队列**（官方 `synchronous_mode.py` 的套路）：

```
import queue
q = queue.Queue()
camera.listen(q.put)            # 出帧就塞队列
while True:
    world.tick()                # 推进一步
    image = q.get(timeout=2.0)  # 阻塞，拿到「这一步」的帧
    assert image.frame == world.get_snapshot().frame   # 用帧号校验对齐
```

多传感器就开多个队列，按 `image.frame`（帧号）对齐。**这是"传感器对齐"从概念落到代码的关键。**

## 4. 实践：CARLA Python client

### 4.1 API 速查（本课最小集）

| 目的 | 调用 |
|---|---|
| 取/改世界设置 | `s = world.get_settings()`；`s.synchronous_mode=True`；`s.fixed_delta_seconds=0.05`；`world.apply_settings(s)` |
| TM 同步 | `tm = client.get_trafficmanager()`；`tm.set_synchronous_mode(True)`；`tm.set_random_device_seed(seed)` |
| 推进一步 | `world.tick()`（同步）/ `world.wait_for_tick()`（异步只观察） |
| 相机蓝图 | `bp = blueprint_library.find('sensor.camera.rgb')`；设 `image_size_x/y`、`fov`、`sensor_tick` |
| 挂相机 | `world.spawn_actor(bp, carla.Transform(carla.Location(x=1.5,z=2.4)), attach_to=vehicle, attachment_type=carla.AttachmentType.Rigid)` |
| 监听 | `camera.listen(callback)`；停 `camera.stop()` |
| 帧号 | `image.frame` / `world.get_snapshot().frame` |

### 4.2 确定性同步循环骨架（先建立结构，写代码前征得同意）

```
设 seed → 设同步+fixed_delta → TM 同步+seed
spawn ego + 传感器(队列) → try:
    for step in range(N):
        world.tick()
        image = q.get()             # 与 tick 对齐
        处理/存盘(image, world 状态)
finally:
    恢复异步设置 + cleanup()         # ★ 不恢复会让下次启动卡死
```

### 4.3 常见坑

- **开了同步忘了 `world.tick()`** → 整个卡死（世界在等你）。
- **退出不恢复异步** → 下次连上去世界还在等 tick，像"假死"。务必 `try/finally` 把 `synchronous_mode` 设回 `False`。
- **BGRA 当 RGB** → 图发蓝（§3.2 翻通道）。
- **不用队列直接读** → 拿到上一帧、图文错位。
- **回调里做重活**（存大图、跑模型）→ 拖慢仿真甚至阻塞 tick；回调只做轻量转存，重活丢到主循环。
- **相机分辨率开太大** → 吃显存（16GB 要省，VLA 输入边长建议 ≤896）。
- **TM 没设同步/seed** → NPC 不可复现。
