## 1. 心智模型①：动作表示是一条谱系

第一课 [§5.8(1)](1-自动驾驶模型.md) 已立这张谱系，本课聚焦中间一档：

```
离散符号/options ──── 轨迹/路点序列 ──── 连续动作 chunk(diffusion/flow)
(本项目 v1)            (本课 v2, AD 主流)      (机器人操作: π0/ACT)
 VLM-planner           UniAD/VAD/EMMA          Diffusion Policy
```

- **v1（前八课）**：高层吐一个符号（`SLOW_DOWN`），控制器沿车道按目标速度走——简单、好调、契合 VLM-API 当大脑。
- **v2（本课）**：高层吐一条**未来 1–3s 的轨迹**（路点 + 速度剖面），下游跟踪 + 每周期重算。这正是 **AD 主流端到端**的输出形态。

> v1 选 options 是**图简单**，不是因为别人不做（第一课 [§5.8(1)](1-自动驾驶模型.md)）。v2 是把表达力升上去、贴近 SOTA。

## 2. 心智模型②：时延陷阱与三种现代解法

第一课 [§5.8(2)](1-自动驾驶模型.md) 的关键澄清：**"陈旧(stale)"是任何低频决策系统的固有属性**（决策基于几百毫秒前的观测），不是某技术落伍。无法消灭，只能让它**不致命**。三种现代解法（本课用前两种）：

| 解法 | 机制 | 本课 |
|---|---|---|
| **滚动重规划**（receding horizon） | 每周期从**最新状态**重算整条轨迹，只执行第一小段 | **v2 核心** |
| **异步 / 实时分块**（RTC、temporal ensembling） | 下一段在上一段执行完前**异步算好、平滑衔接** | 可选 v3 |
| 底层闭环 + 高频反射层 | 底层每 tick 反馈 + AEB 可覆盖 | v1 就有，继续保留 |

## 3. 必须知道的原理

### 3.1 轨迹级输出：高层吐什么

v2 的高层（VLA/规划器）不再吐符号，而是吐**一条带时间的轨迹**：

$$
\tau = \{(x_k, y_k, v_k, \psi_k)\}_{k=1}^{H}
$$

未来 $H$ 步的位置/速度/朝向序列（如 1–3s）。它把"该做什么"具体成"具体怎么走"——这就是第一课 [§5.3](1-自动驾驶模型.md)/[第三课](3-控制与行人.md) 里**被 v1 省掉的"规划器"**（轨迹/运动规划那一层）重新加回来。

### 3.2 滚动重规划（receding horizon / MPC）

核心循环：

```
每个规划周期:
  1. 用当前(最新)状态 + 感知/预测，规划一条 H 步的轨迹 τ（满足：车道约束、避碰、动力学可行、舒适）
  2. 只执行 τ 的第一小段(几个控制步)
  3. 丢掉其余，下周期用更新后的状态从头再规划
```

- **MPC（模型预测控制）**：把第 1 步写成一个**带约束的优化**（用车辆模型预测、最小化偏离+不适+风险）。本课可简化：高层 VLA/规划器出轨迹，下游用 **MPC 或纯跟踪（Pure Pursuit，第三课 [§3.3](3-控制与行人.md)）** 跟踪。
- **为什么抗陈旧**：每周期都用最新状态重算，陈旧窗口缩到一个周期（对比 v1 的宏动作横跨更久）。

### 3.3 v2 vs v1 options：到底差在哪

| | v1 options（前八课） | v2 轨迹 + 滚动重规划 |
|---|---|---|
| 高层输出 | 一个符号 | 一条 H 步轨迹 |
| 下游 | 控制器沿车道按目标速度 | MPC/纯跟踪这条轨迹 |
| 重决策 | 1–2Hz 重选符号 | 每周期从最新状态重算轨迹 |
| 表达力 | 粗（约束在车道+离散动作） | 细（能表达绕行曲线、速度剖面） |
| 复杂度/贴 SOTA | 低 / 一般 | 高 / 贴 AD 主流 |

> 注意：**两者都"重规划"**（v1 也 1–2Hz 重选）。真正差别是**输出的丰富度**（符号 vs 轨迹）与是否显式优化一个时域（第一课 [§5.8](1-自动驾驶模型.md)）。

### 3.4 （可选 v3）异步推理 / 实时分块

让慢 VLM **不阻塞控制**：在当前段执行期间，后台异步算下一段，算好平滑衔接（Real-Time Chunking / temporal ensembling）。这样既低频推理、又永不开环回放陈旧动作。CARLA 同步模式下其实没有"撞车"压力（时间红利，第一课 [§5.5(5)](1-自动驾驶模型.md)），v3 更多是为**贴近真实部署形态**而做的演示/研究。

### 3.5 AD SOTA 对标（面试能说）

- **端到端轨迹**：UniAD（CVPR'23 best paper，规划导向端到端）、VAD/VADv2（矢量化）、EMMA（Waymo，多模态 LLM→轨迹）、DiffusionDrive（扩散轨迹）。
- **世界模型**：GAIA-1/2（Wayve，生成式世界模型做预测/造数据）。
- **机器人 chunk**：π0（flow matching 动作块）、Diffusion Policy、ACT。
- 你的项目位置：**双系统分层 VLA**，v1=离散 options，v2=轨迹级（贴端到端轨迹范式）。

## 4. 实践：v2 agent

### 4.1 骨架（写代码前征得同意）

```
class TrajVLAAgent(同闭环接口):
    def run_step(self, obs):
        每规划周期: τ = 高层.plan_trajectory(obs)        # 高层吐 H 步轨迹(VLA 或规划器)
        ctrl = tracker.run_step(当前状态, τ)              # MPC/纯跟踪 → VehicleControl
        # 下周期用最新 obs 重新 plan_trajectory(滚动重规划)
        return ctrl
# 与 v1 共用场景/指标(第四/五课)，做 v1 vs v2 对比
```

### 4.2 常见坑

- **在 MVP 前做** → 本末倒置；先把第一~八课闭环交付。
- **轨迹跟踪器没调好** → 画龙/超调（同第三课 PID 坑，[§4.4](3-控制与行人.md)）。
- **重规划周期太长** → 陈旧窗口大、贴不住动态目标；太短 → 算不过来。
- **v3 异步时序对齐复杂** → 段与段衔接没处理好会抖动；先把 v2 同步版做稳。
- **拿 v2 当"必须项"** → 它是选修；三方 ablation 不依赖它（第八课 [§1](8-三方评测与论文.md)）。

## 5. 验收 & 自测题

**操作验收（选修）**
- [ ] 高层能吐一条 H 步轨迹；下游 MPC/纯跟踪能跟住、不画龙。
- [ ] 每周期从最新状态滚动重规划；v2 agent 在鬼探头场景跑通。
- [ ] 做出 v1（离散）vs v2（轨迹）的对比（成功率/安全指标/平顺性）。

**概念自测（能用自己话答上即过关）**
1. 动作表示谱系三档分别是什么？本项目 v1/v2 各在哪档？
2. "陈旧(stale)"为什么消灭不了？三种现代解法分别怎么让它不致命？
3. v2 和 v1 都"重规划"，真正的区别是什么？
4. 滚动重规划/MPC 的核心循环是什么？为什么抗陈旧？
5. 说出 3 个 AD 端到端/世界模型 SOTA，并定位你的项目在谱系里的位置。
